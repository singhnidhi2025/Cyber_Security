## Chapter 1:Foundations:
### Terminology
-	PlainText: Message which needs to be sent
-	Encryption: The process of disguising the message
-	Decrpytion: the process of converting the encrypted message back into plain text.
-	Ciphertext: Encrypted message.(Schneier, 2015)

In addition to confidentiality,cryptography also provides:
  - **Authentication**:The person receiving a message should be able to confirm who actually sent it. No outsider should be able to pretend to be someone else.
  - **Integrity**:The receiver should be able to check that the message was not changed while being sent. No intruder should be able to replace it with a fake message.
  - **Nonrepudiation**:The sender should not be able to deny later that they were the one who sent the message.(Schneier, 2015)
## Algorithms and keys:
- **Cryptographic algorithm**:mathematical method used to encrypt and decrypt information.	
- **Restricted Algorithm**: When the algorithm is kept secret.
- **Key**: Used for encryption and decryption
- **Keyspace**: Range of possible values of the key.
- **Cryptosystem**: Algorithm plus all possible plaintexts,ciphertexts,and keys.
- **Symmetric Algorithms**: where encryption key can be calculated from decryption key, often, both are same.
- **Public Key Algorithms**: Kyes used for encryption and decryption are different.(Schneier, 2015)

## Chapter 2:Protocol Building Blocks:
### Communications Using Public-Key Cryptography
- A **Public Key** is required to encrypt the message(anyone can have access to it), however, only someone having access to the **private key** can decrypt the message.
#### **Hybrid Cryposystems**: 
Public-Key algorithms have certain limitations such as they are slow and and vulnerable to choosen-plaintext attacks.
Hence, **Hybrid Cryptosystem** is used to secure and distrubute **session keys** which are used with symmetric algorithms.(Schneier, 2015)
#### Merkel's Puzzels:
It was based on puzzels that were easier to solve for sender and reciever than th eavsedropper.
- Bob creates many encrypted “puzzles,” each containing a unique puzzle number and secret key, and sends them all to Alice.
- Alice randomly picks one puzzle, brute-forces it to find the secret key, and uses that key to encrypt her message and send it back with the puzzle number.
- Bob identifies the puzzle number, retrieves the matching secret key, and decrypts Alice’s message.(Schneier, 2015)

# a) Pubkey today
- When thinking about public key cryptograpghy the most obvious answers that we use almost on daily basis are **HTTPS** secure websites.The one i used recently was my online banking webpage.
- The website (server) uses a public key in its **digital certificate**. The browser downloads this certificate when I connect.
- The browser (client) uses the server’s public key to verify the server’s identity and to encrypt a session key that only the server can decrypt with its private key.
- After this exchange, both the browser and the server share the same session key, which is then used with symmetric encryption to protect all communication.(Quecko, n.d.)
  So, public key cryptography is used for:
- **Authentication** (verifying the real server)
- **Secure key exchange** (encrypting the session key with the server’s public key)
  
# b) Encrypt a message
- When I logged in to my online banking website, HTTPS protected all communication using public key cryptography.
- **Bank’s public key**:My browser received the bank’s public key in its certificate. It used this key to verify the bank’s identity and to encrypt a randomly generated session key.
- **Bank’s private key**:The bank used its private key to decrypt the session key. Only the legitimate server has this private key.
- **Session key (symmetric key)**:After this exchange, both my browser and the bank shared the same session key.All actual data—logins, account details, and transactions—was encrypted using this symmetric key.
- **Security evaluation**:HTTPS is considered very secure because it provides authentication, strong encryption, and protection against eavesdropping. Modern HTTPS also supports forward secrecy, making past sessions safe even if keys are compromised later.(Cloudflare, 2025)

# c) Eve and Mallory
Eve is a passive eavesdropper who listens to messages but does not change them, while Mallory is an active attacker who can modify, intercept, or inject messages.
PGP protects against both as follows:
### 1. Protection Against Eve (Eavesdropping): 
- PGP uses public-key encryption to encrypt the message.
- The sender uses the recipient’s public key to encrypt the message.
- Only the recipient’s private key can decrypt it.
- **Result:** Even if Eve intercepts the encrypted message, she cannot read it without the private key.(SentinelOne, 2025)
### 2. Protection Against Mallory (Message Modification):
- PGP allows the sender to digitally sign the message using their private key.
- The recipient can verify the signature using the sender’s public key.
- **Result:** If Mallory modifies the message in transit, the signature check fails, alerting the recipient to tampering.
This ensures integrity and authenticity.(SentinelOne, 2025)
### 3. Relevant PGP Features and Command Flags:
- **Encryption:** Use the recipient’s public key for confidentiality (protection from Eve).
              gpg --encrypt --recipient recipient@example.com message.txt
- **Signing:** Uses the sender’s private key to create a signature (protection from Mallory).
              gpg --sign message.txt
- **Combined Encrption and Signing:** for eg.   gpg --homedir . --encrypt --recipient tero@example.com.invalid --sign --output encrypted.pgp --armor message.txt (Karvinen, 2023)

Types of attacks that exploit weak or reused passwords (Trevino, A. 2024):
- **Brute Force Attacks:** Attackers try many combinations until the password is guessed. Weak or predictable passwords are highly vulnerable.
- **Dictionary Attacks:** Attackers use lists of common words or phrases to guess passwords.
- **Password Spraying:** Common passwords are tested across many accounts; reused passwords make this effective.
- **Credential Stuffing:** Previously leaked passwords are tried on other websites; reused passwords make multiple accounts vulnerable.
- **Rainbow Table Attacks:** Precomputed tables of password hashes are used to reverse-engineer passwords.

Using a password manager like Chrome’s helps reduce the risks associated with poor password habits. Without a password manager, people are more likely to fall to attacks:
- **Reuse passwords** across multiple sites, so a breach on one site can compromise many accounts.
- **Use weak or easily guessable passwords**, such as “123456” or “password.”
- **Fall victim to phishing attacks**, where attackers trick users into entering passwords on fake websites.
- **Store passwords insecurely**, such as in plain text files or sticky notes, which can be easily stolen.
Password managers mitigate these risks by generating strong, unique passwords for each account and storing them securely, reducing the likelihood that attackers can exploit human password weaknesses.
